# 手工验收清单

对应 `docs/复刻方案.md` 11.2 的验收标准。自动化门禁（ESLint、`vue-tsc`、Vitest、`cargo clippy -D warnings`、`cargo test`）由 CI 在 Windows/Ubuntu/macOS 三个 runner 上跑，本清单只覆盖**必须真机点**的部分：安装、托盘、自启、真实设壁纸、桌面环境差异。

用法：每台设备一行，把结果写成 `通过 / 失败(现象) / 不适用`，附系统版本与应用版本。失败的项在对应 Issue 里描述，不要只在本文件打叉。

## 1. 通用检查项（每个平台都跑一遍）

| # | 行为 | 步骤 | 期望 |
|---|---|---|---|
| 1 | 安装与首启 | Windows 双击安装包 / macOS 拖 `.app` 进「应用程序」/ Linux `sudo dpkg -i *.deb` | 当前用户可安装（无需管理员）；首启显示引导态，图片目录自动创建 |
| 2 | 取图 | 首页等待今日图加载 | 显示必应当日图、标题与版权；断网时报可读错误而不是空白 |
| 3 | 设壁纸 | 首页「立即设置」 | 桌面真的换了图；应用日志出现成功记录 |
| 4 | 契合度 | 设置页切换 6 种模式，每种点一次「立即设置」 | 本平台不支持的模式**置灰不可选**；下拉里只剩支持项 |
| 5 | 契合度钳制 | 选一个支持的模式 → 完全退出 → 改 settings.json 把 `wallpaper_style` 写成该平台不支持的值 → 重启 | 启动后设置回落到「填充」，settings.json 被重写，日志有一条 warn |
| 6 | 托盘与关窗 | 打开/关闭「关闭按钮最小化到托盘」开关，各点一次标题栏关闭 | 开着：窗口隐藏、进程存活，托盘菜单「显示主窗口 / 立即设置壁纸 / 打开图库 / 设置 / 退出」四项都能用；关着：点关闭进程直接结束 |
| 7 | 自启 | 打开「开机自启」→ 注销再登录 | 应用自动起且最小化到托盘；关掉后不再自启 |
| 8 | 定时 | 设一个近的时间点 → 挂着等 | 到点自动取图并设置；跨天/错过的时间点重启后补跑一次 |
| 9 | 批量下载 | 选 7 天区间开始，中途取消，再重新跑 | 进度条与日志滚动；取消后任务停；重跑时已存在的日期计为跳过 |
| 10 | 图库 | 分页/搜索/收藏/设壁纸/删除 | 翻页不丢状态；收藏持久；删除 App 自己下载的图片时**文件与缩略图一起删** |
| 11 | 目录扫描 | 设置页把保存目录指到一个已有几百张壁纸的文件夹 → 重启 | 后台先建索引再补缩略图，进度事件驱动进度条；首屏不被拖慢 |
| 12 | 外部图片保护 | 上一步扫描出的图片里删几张 | 只解除索引，**用户目录里的原文件不被删除**；再次重启扫描不会重新导入已删的 |
| 13 | 更新检查 | 关于页点「检查更新」 | 列出比当前新的 Release；「前往下载」打开 Release 页面 |
| 14 | 界面 | 切中英文、切暗色、缩到最小尺寸 900×600 | 文案完整不溢出；暗色下对比度可用；无控件被裁掉 |
| 15 | 卸载 | 从系统「添加或删除程序」卸载 | 卸载后图片目录与 settings.json 按预期保留（用户数据不清） |

## 2. 平台专项

### Windows 10 / 11 x64

- [ ] `IDesktopWallpaper` COM 路径生效：多显示器接「跨区(span)」与单屏「填充」都正确。
- [ ] 注册表回退路径：禁用/不可用 COM 的场景（如某些精简系统）仍能通过 `SystemParametersInfoW` + HKCU 设置成功。
- [ ] 每显示器分别设置（`multiMonitor` 能力为 true 时）。

### Windows 11 ARM64

- [ ] 安装包为 ARM64 且能装（若只出 x64，确认 Windows on ARM 能跑 x64/arm64 .emu 包并记录）。
- [ ] 通用检查项 1–15。

### macOS 13 / 14 / 15（Intel 与 Apple Silicon 各一次）

- [ ] 首次设壁纸触发 **自动化授权**（「BingWallpaper 想要控制访达」，后端走 `osascript`）；同意后设图成功。
- [ ] 拒绝授权后再点「立即设置」：错误提示能指向 系统设置 → 隐私与安全性 → 自动化，而不是只报一句失败。
- [ ] 契合度只有「填充」可选，其余置灰。
- [ ] `.app` 从「下载」目录拖到「应用程序」后可运行；未签名提示（右键 → 打开）能绕过。
- [ ] Dock 行为：窗口隐藏后 Dock 图标仍在，但**当前版本没有处理 `applicationShouldHandleReopen`**，点 Dock 图标不会唤回窗口——记录现象，确认用托盘菜单「显示主窗口」可以找回。
- [ ] 通用检查项 1–15。

### Ubuntu 22.04 / 24.04 x64 + ARM64（GNOME）

- [ ] `.deb` 装得上（依赖 `libwebkit2gtk-4.1-0`、`libayatana-appindicator3-1` 能解析）。
- [ ] `gsettings` 写入壁纸成功，且**多显示器**时两个屏幕都换。
- [ ] GNOME 顶栏托盘：AppIndicator 图标可见（需要扩展时记录扩展名）。
- [ ] 通用检查项 1–15。

### KDE Plasma

- [ ] `plasma-apply-wallpaperimage` 存在时能设图；不存在时的错误信息可理解。
- [ ] Plasma 6 下确认设置的壁纸不会被 KDE 自己的壁纸配置覆盖。

### XFCE

- [ ] `xfdesktop` 设置生效（记录是否要求开「桌面」组件）。

### Sway

- [ ] `swaymsg output * bg <path> <mode>` 生效；6 种契合度映射按 `sway_mode` 预期（`span` 归为 `fill`）。

### Hyprland / 其他（可选）

- [ ] `hyprctl hyprpaper` 路径：先 `unload all` 再 `preload`，切图不残留。
- [ ] 只有 `feh` 的环境：`feh --bg-*` 生效，`span` 归为 `--bg-fill`。

## 3. 性能与产物体积

验收线（方案 11.2）：冷启动 < 2s（不含网络）、常驻内存 < 150MB、安装包 < 20MB。

测量方法：

```bash
# Windows PowerShell —— 冷启动（先杀掉进程再计首次显示窗口耗时）
Measure-Command { Start-Process "$env:LOCALAPPDATA\BingWallpaper\BingWallpaper.exe" -PassThru }
Get-Process BingWallpaper | Select-Object WorkingSet64, PrivateMemorySize64

# macOS —— 常驻内存（KB）
ps -o rss= -p "$(pgrep -n BingWallpaper)"

# Linux —— 常驻内存（KB）
ps -o rss= -p "$(pgrep -n bingwallpaper)"
```

| 平台 / 架构 | 冷启动 | 常驻内存 | 安装包体积 | 记录人 |
|---|---|---|---|---|
| Windows 11 x64（本机 GNU 构建） | 待填 | 待填 | 待填 | |
| Windows 11 x64（CI MSVC 产物） | | | | |
| Windows 11 ARM64 | | | | |
| macOS 15 Apple Silicon | | | | |
| macOS 15 Intel | | | | |
| Ubuntu 24.04 x64 | | | | |
| Ubuntu 24.04 ARM64 | | | | |

> 本机与 CI 的 Windows 产物来自不同工具链（`x86_64-pc-windows-gnu` / `x86_64-pc-windows-msvc`），内存与体积会有差异；以 **CI 产物**为准，本机数值只作参考。
